1. **让 Codex 拆分项目任务。**

   把下面这段话发给 Codex：

   > 阅读 README.md、docs/project-design.md、docs/adr/ 下的文档和现有代码，告诉我已经完成了什么、还缺什么。把剩余工作拆成小任务，按开发顺序写到 docs/backlog.md。每个任务写清楚做什么、怎样检查是否完成。先不要写代码。

2. **每次选一个任务，先看方案。**

   > 从 docs/backlog.md 中选择下一个任务，说明需要改哪里、准备怎么做、完成后怎么验证。用小白能理解的话解释，先不要修改代码。

   看不懂就让 Codex 解释。确认后发送：

   > 把选中的任务写到 docs/backlog.md 的“当前任务”部分，记录任务名称、目标、实现方案和验收条件，再记录当前分支与开始修改前的提交编号，供后续审查定位改动。暂时不要实现功能。

3. **让 Codex 实现这个任务。**

   > 阅读 docs/backlog.md 的“当前任务”部分，按其中的方案完成任务，补充必要的测试和文档。只做这个任务，完成后不要自动开始下一个任务。

4. **让 Codex 运行测试。**

   > 运行与本次修改有关的测试，失败就排查并修复。告诉我实际运行了什么、结果如何、哪些没有运行。涉及数据库时，使用 README 中的独立数据库测试环境，确认集成测试没有被跳过。

5. **新开一个 Codex 会话，检查代码。**

   > 阅读 docs/backlog.md 的“当前任务”部分，了解目标、方案和验收条件。根据其中记录的分支和起始提交，检查本次任务的代码改动，包括尚未提交和新建的文件。检查有没有功能错误、遗漏场景，以及是否违反现有 ADR。先只报告问题，不修改代码。每个问题说明什么情况下会发生、会造成什么结果。

   把发现的问题交给原来的会话修复，再重新测试。

6. **自己运行一次，确认能用、能讲清楚。**

   > 给我最简单的操作步骤，让我亲自验证这个功能。然后用通俗的话解释这次修改，让我能说清楚：解决了什么问题、代码怎样工作、失败时怎么处理。

   按步骤操作。遇到报错或不理解的地方，继续让 Codex 排查或解释。

7. **提交代码，记录进度，再做下一项。**

   > 检查本次修改，给我提交消息；把任务完成情况、测试结果和下一步更新到 docs/backlog.md。如果还有未解决的问题，如实记录，不要标记为完成。

   确认后提交代码。下一项任务重新从第 2 步开始；新会话先让 Codex 阅读 docs/backlog.md。
