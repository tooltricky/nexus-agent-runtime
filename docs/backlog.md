# 开发待办与进度

## 当前状态

截至 2026-11-06，项目是带租约、有限重试、原子取消和短事务执行的单任务 Runtime 骨架，B01–B08 已完成；当前保留 B08“持久化截止时间与超时处理”的方案、审查基线与本地验收记录，未开始 B09。B03 的 CI 工作流、报告检查器、JAR 打包和 GitHub Actions 实跑均已验证；B05–B08 已通过本地独立 PostgreSQL 验收。详细背景见 [README](../README.md)、[项目设计](project-design.md) 和 [ADR](adr/)。本文件只保留当前任务、未完成路线和精简完成记录；具体实现细节以代码和 Git 提交为准。

设计说明书是目标蓝图，ADR 是当前已接受的落地决策。继续优先采用 Spring Boot 模块化单体和 PostgreSQL；不把引入全部语言、中间件或拆分服务作为下一步的前置条件。改变既有语义或引入部署边界时补充 ADR。特别是 ADR 0003 已取代 ADR 0002 中“租约过期立即回到 PENDING”的行为。

## 任务执行规则

- B01–B08 已完成，B09 及后续任务仍为“待办”；编号给出推荐开发顺序，“依赖”列列出主要直接依赖。一次只选一个任务，完成后再选下一项。
- 每项都要形成独立、可审查的交付。表中“做什么”是范围，“怎样检查完成”是必须满足的验收条件；不是看到类名、接口或配置文件就算完成。
- 当前任务保留完整方案、验收条件和审查基线；任务完成并切换到下一项时，将其压缩为完成日期、提交编号、关键验证结果及未解决 / 未验证事项，不累计完整方案或逐项测试日志。长期设计和操作说明分别维护在 ADR 与 README，历史实现按需查 Git；确需单独留存的验收材料只在此提供链接。
- 功能有数据库、状态、HTTP 或事件变化时，同步更新迁移、OpenAPI / JSON Schema、必要测试和 README；不回改已经应用的 V1–V3 迁移。新增状态不能只改 Java 枚举。
- 数据库验证使用 README 的独立测试库：`docker compose -f deploy/docker-compose.test.yml up --abort-on-container-exit --exit-code-from tests`，检查测试报告确认数据库集成测试实际执行、未被跳过，再用同一 Compose 文件 `down` 清理。禁止连接演示或业务数据库跑清表测试。
- 单体内部先建立接口和事务边界；需要独立 Python / Go / TypeScript 组件时，先明确状态唯一写入方和服务认证，不让多份实现各自决定同一个 Task 的终态。
- 模型和下游工具测试优先使用可控桩，真实联调另记结果；外部副作用不因数据库租约而天然“恰好一次”。未做验证和已知问题必须保留在当前任务或完成记录中。
- 设计里的安全、性能和覆盖率数字是目标，只有有脚本、环境说明和实际报告后才能标记达成。
